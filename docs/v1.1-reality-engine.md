# Procedural City v1.1 현실성 엔진 설계

## 1. 목표와 판정 기준

v1.1의 목표는 건물 모양만 복잡하게 만드는 것이 아니라, 도시의 각 결과가 앞 단계의 공간 조건에서 설명되도록 만드는 것이다.

현실성은 다음 네 기준으로 판정한다.

1. **인과성**: 건물은 도로와 필지 없이 생기지 않으며 용도와 높이는 접근성·경사·수해 위험의 결과여야 한다.
2. **위계성**: 간선·집산·생활가로, 중심지·부도심, 포디움·타워·입면 모듈의 규모 위계가 있어야 한다.
3. **공간 제약**: 물, 급경사, 범람지, 도로 전면, 필지 중복과 같은 지역 제약을 생성 단계에서 처리해야 한다.
4. **정직성**: 합성 모델을 실제 서울 데이터나 BIM 디지털 트윈으로 표시하지 않는다.

## 3. 시스템 분리

### 3.1 Terrain & Hydrology Core

입력은 시드, 격자 크기, 세계 크기, 기복, 해수면이다. 출력은 서로 같은 격자에 정렬된 다음 필드다.

```text
height / filledHeight / slope / aspect
downstream / accumulation / channelStrength
water / distanceToWater / floodRisk
soil / vegetation / buildability
```

원래 고도는 시각 지형으로 보존하고, 배수 보정 고도는 흐름 방향 계산에만 사용한다. 따라서 함몰부를 제거하면서도 지형의 시각적 굴곡을 과도하게 평탄화하지 않는다.

### 3.2 Urban Morphology Core

도시 코어는 지형 샘플러만 소비하며 렌더링 함수를 사용하지 않는다.

```text
centers[] → roads[] → transit → parcels[] → land use → buildings[]
```

- 중심지는 개발 적합도, 중심성, 수변 편익, 경사와 침수 위험으로 평가한다.
- 간선은 중심업무지구와 각 부중심을 연결하고, 집산도로는 부중심을 연결한다.
- 생활가로는 중심지 주변의 등고 방향과 그 직교 방향을 따른다.
- 필지는 도로 선분에서 일정 간격으로 샘플링하고 도로 폭·보도·셋백 뒤에 배치한다.
- 공간 해시로 인접 필지의 중복을 억제한다.
- 용도와 FAR은 중심지 거리, 역 거리, 도로 등급, 수변, 경사, 침수 위험으로 결정한다.

### 3.3 Rendering & Material Core

렌더러는 도시 의미 객체를 단일 WebGL 정점 버퍼로 변환한다. 정점 형식은 기존 호환성을 위해 position·normal·color의 9개 float를 유지한다.

재질 매개변수를 별도 attribute로 늘리는 대신 색·법선·표면 방향을 조합해 유리, 물, 아스팔트, 금속, 식생을 분류한다. 건물 수직면에는 세계 좌표 기반의 층·bay 격자를 생성해 창호를 표현한다.

## 4. 주요 설계 수치

| 항목 | v1.1 기본값 | 의미 |
|---|---:|---|
| 간선도로 포장 폭 | 20 m | 4차로와 중앙부 표현 |
| 집산도로 포장 폭 | 13 m | 2차로와 보도 |
| 생활도로 포장 폭 | 7.2 m | 저속 2차로 |
| 보도 폭 | 2.2–3.6 m | 도로 위계별 차등 |
| 대중교통 접근 반경 | 500 m | 계획 모델의 도보 접근 판정 |
| 개발 경사 상한 | 약 17.5° | 합성 필지 생성 제한 |
| 건물 높이 상한 | 일반 46층, 대도시형 58층 | 시나리오별 스카이라인 제한 |
| 렌더 목표 | LOD2-like | 지붕·외부 매스·입면 리듬 표현 |

이 값들은 시각적 도시 생성기의 보수적 설계 가정이다. 특정 한국 도로의 법정 폭원이나 실제 대지의 허가 가능성을 판정하는 수치가 아니다.

## 5. `seoul-2040` 기준 회귀 결과

자동 테스트 환경의 수변 복합도시, 30×30, 개발 강도 68%, 기복 14 조건:

| 항목 | 결과 |
|---|---:|
| 지형 셀 | 6,724 |
| 중심지 | 5 |
| 도로 회랑 | 72 |
| 도로 전면 필지 | 172 |
| 렌더 건축물 | 약 175 |
| 렌더 정점 | 약 268,000 |
| 도로 선분 | 약 852 |
| 생성 시간 | Node 기준 약 1초 |

정확한 수치는 브라우저·시나리오·세부도에 따라 달라지지만 같은 시드와 설정에서는 동일한 공간 결과를 재현한다.

## 6. 남은 한계와 다음 단계

- 실제 DEM·지적도·OpenStreetMap을 읽지 않으므로 현재는 합성 도시다.
- 그림자 지도, 환경 맵, 텍스처 atlas가 없어 사진 수준 PBR에는 미치지 못한다.
- 도로 선형은 완화곡선·종단곡선·절성토 물량까지 계산하는 토목 설계가 아니다.
- 건물은 외부 매스 중심이며 구조체·실내·설비는 생성하지 않는다.
- 교통은 경로를 가진 시각 에이전트이나 신호 최적화·미시 교통류 모델은 아니다.

다음 현실성 단계는 실제 DEM/GeoJSON/OSM 가져오기, 타일·인스턴싱, 그림자 패스, 도로 종횡단 설계, 토지가격·통근 수요와 개발 사업성 모듈이다.
