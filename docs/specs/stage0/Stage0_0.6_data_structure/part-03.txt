48. 데이터 검증 시나리오
────────────────────────────────────────

시나리오 A: 개체 파괴 후 과거 사건 조회

잘못:
개체 삭제와 함께 모든 참조 무효화

올바름:
EntityRecord destroyed
→ EntityTombstone 생성
→ 과거 Event와 Memory가 Tombstone 참조

시나리오 B: AI가 식량 위치를 앎

잘못:
BeliefRecord가 Terrain ResourceDeposit의 실제 좌표를 자동 복사

올바름:
ObservationRecord
→ MemoryRecord
→ BeliefRecord
→ 불확실한 위치 추정

시나리오 C: 자원 이동

잘못:
경제 모듈이 실제 물질 수량 직접 변경

올바름:
ExchangeAgreement
→ Transfer Command
→ Physics/Ecology StateDelta
→ Commit
→ Transfer Event
→ Economy fulfillment 갱신

시나리오 D: LOD 강등

잘못:
개체 삭제 후 인구 수만 저장

올바름:
PopulationCohort
+ ResourceAccount
+ RelationshipDistribution
+ KnowledgeDistribution
+ important entities
+ reconstruction seed
+ causal links

시나리오 E: 저장 복원

잘못:
현재 위치와 화면 상태만 저장

올바름:
WorldSaveManifest
+ Module states
+ EntityRegistry
+ Random streams
+ Event position
+ interventions
+ schema versions
+ checksums

시나리오 F: 도시 분류

잘못:
CityState를 권위 상태로 생성

올바름:
RegionSummary와 활동·인구·구조 패턴
→ Observation Classification
→ "도시형 패턴" Read Model

49. 금지 데이터 패턴
────────────────────────────────────────

- 전역 WorldState 하나에 모든 데이터 저장
- 동일 사실을 여러 모듈이 권위 상태로 중복 보유
- 실제 상태와 BeliefState 혼합
- Event를 문자열 로그로만 저장
- ID 대신 배열 인덱스를 영구 참조
- 코드 enum 순서를 저장값으로 사용
- 단위 없는 물리 수치
- 원인 없는 StateDelta
- revision 없는 가변 상태
- 저장되지 않는 장기 Command
- 파괴된 개체 참조를 무조건 제거
- LOD 강등 시 인과·지식·관계 삭제
- RenderSnapshot을 시뮬레이션 입력으로 재사용
- 카메라 거리만으로 데이터 정밀도 결정
- 알 수 없음과 0을 혼동
- 스키마 버전 없는 저장
- 마이그레이션 없는 의미 변경
- 정렬되지 않은 Map 순회로 결정론 훼손
- 캐시를 권위 상태로 취급
- 분석 라벨을 시뮬레이션 상태로 승격
