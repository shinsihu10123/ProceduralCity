Stage 0.6 데이터 구조 명세

문서 버전: 0.6.0
상태: 기준안 확정
적용 범위: 프로젝트 전체 런타임 상태, 명령, 사건, 저장, 분석, LOD, 스키마
상위 문서:
- Stage 0.1 프로젝트 철학 및 시스템 경계 명세
- Stage 0.2 핵심 원칙 및 강제 규칙 명세
- Stage 0.3 전체 아키텍처 명세
- Stage 0.4 개발 규칙 명세
- Stage 0.5 코드 구조 명세

목적:
인공 세계의 모든 중요 데이터를 권위 상태, 행위자 인식 상태, 변경안, 사건,
집계 상태, 저장 상태, 분석 상태로 구분하고, 각 데이터의 필드·수명·소유권·참조·
버전·직렬화·무결성·LOD 전환 규칙을 정의한다.

────────────────────────────────────────
1. 기본 데이터 원칙
────────────────────────────────────────

1.1 단일 권위 상태

동일한 사실을 둘 이상의 모듈이 권위 상태로 중복 소유하지 않는다.

예:
- 위치와 속도: Physics
- 체온과 부상: Biology
- 기억과 믿음: Cognition
- 신뢰와 의무: Society
- 사건 기록: EventLedger

다른 모듈이 동일 사실을 필요로 하면 Query, Snapshot, Event 또는 파생 캐시를 사용한다.

1.2 실제 세계와 인식 세계의 분리

다음 두 상태는 명확히 분리한다.

World Truth
- 시뮬레이션 내부의 실제 상태

Epistemic State
- 개체가 관찰·기억·추론·전달을 통해 믿는 상태

행위자는 World Truth를 직접 사용하지 않는다.

1.3 권위 상태와 파생 상태의 분리

Authoritative State
- 세계 진행을 결정
- 저장 필수
- 소유 모듈만 변경

Derived State
- 권위 상태에서 다시 계산 가능
- 저장 선택
- 캐시 폐기 가능

Presentation State
- 렌더링·UI용
- 시뮬레이션 판단에 사용 금지

1.4 모든 상태 변경의 원인

권위 상태 변경은 다음 중 하나를 원인으로 가져야 한다.

- Command
- 자연 과정
- 선행 Event
- 시스템 초기화
- 기록된 Intervention
- 문서화된 수치 오차 보정

1.5 데이터 지향성

대규모 개체 처리를 위해 데이터는 객체 그래프보다 연속 배열, 컴포넌트 저장소,
지역별 파티션, 안정 ID와 인덱스를 우선 사용한다.

단, 외부 계약과 저장 형식은 내부 메모리 배치에 종속되지 않는다.

1.6 스키마 우선

Command, Event, Snapshot, Save, Config는 코드보다 독립된 버전 스키마를 가진다.

1.7 무한 실행 대응

다음 데이터는 무한히 증가할 수 있으므로 수명과 압축 정책을 명시한다.

- 사건
- 기억
- 관계 이력
- 경로 이력
- 지식 계보
- 성능 기록
- 저장 스냅샷

2. 데이터 분류 체계
────────────────────────────────────────

A. Authoritative State
세계의 실제 진행을 결정한다.

예:
- TerrainState
- BodyState
- PhysicalBodyState
- BeliefState
- RelationshipState
- KnowledgeState

B. Epistemic State
행위자와 집단이 믿는 세계 모델이다.

예:
- Observation
- MemoryRecord
- BeliefRecord
- RumorRecord
- ConfidenceEstimate

C. Intent & Command
아직 발생하지 않은 행동 시도다.

예:
- MoveIntent
- ConsumeIntent
- AttachIntent
- CommunicateIntent

D. Resolution Data
판정 과정의 중간 결과다.

예:
- ValidationResult
- ResourceReservation
- StateDelta
- CommitBatch

E. Event Data
이미 발생한 사실과 인과관계를 기록한다.

예:
- MovementCompleted
- ConsumptionFailed
- StructureCollapsed
- DeathOccurred

F. Aggregate State
LOD 강등 지역의 보존 상태다.

예:
- RegionAggregateState
- PopulationCohort
- ResourceAccount
- KnowledgeDistribution

G. Snapshot & Read Model
렌더링·UI·분석용 읽기 데이터다.

예:
- RenderSnapshot
- EntityView
- RegionSummary
- CausalGraphView

H. Persistent Data
저장·복원을 위한 직렬화 데이터다.

예:
- WorldSnapshotManifest
- ModuleStateSegment
- EventSegment
- RandomStateManifest

I. Configuration Data
세계 규칙과 실험 조건이다.

J. Diagnostic Data
성능·불변 조건·디버그 추적 데이터다.

3. 공통 원시 타입
────────────────────────────────────────

3.1 Tick

type Tick = unsigned 64-bit integer

규칙:
- 0은 초기 상태
- 매 시뮬레이션 스텝마다 1 증가
- 오버플로는 실질적으로 발생하지 않도록 충분한 범위 사용
- 저장과 Event의 기준 시간

3.2 SimulationDuration

fields:
- ticks: unsigned 64-bit

선택적 읽기 표현:
- seconds
- minutes
- days
- years

읽기 표현은 설정된 tick_duration을 사용해 변환한다.

3.3 WorldTime

fields:
- tick
- elapsed_duration
- calendar_id
- calendar_position

calendar_position은 표현용이며 권위 기준은 tick이다.

3.4 Strong ID

공통 구조:

StrongId:
- value: unsigned 64-bit 또는 128-bit
- generation: unsigned integer
- type_tag: 컴파일 타임 또는 스키마 타입으로 분리

필수 ID:
- WorldId
- ModuleId
- EntityId
- ComponentId
- RegionId
- CellId
- CommandId
- EventId
- ObservationId
- MemoryId
- BeliefId
- RelationshipId
- KnowledgeId
- StructureId
- SaveId
- SnapshotId
- ExperimentId
- InterventionId
- RandomStreamId

규칙:
- ID와 배열 인덱스를 동일하게 취급하지 않음
- 폐기된 ID를 즉시 재사용하지 않음
- 재사용 시 generation 증가
- 외부 저장에는 안정 ID 사용
- 내부 캐시는 ID→index 매핑 사용 가능

3.5 SchemaVersion

fields:
- major
- minor
- patch
- schema_hash

3.6 StableTypeId

문자열 또는 명시적 정수.

예:
- "physics.body.v1"
- "event.movement.completed.v1"

코드 enum 순서에 의존하지 않는다.

3.7 HashDigest

fields:
- algorithm
- bytes

용도:
- 결정론 digest
- 저장 체크섬
- 설정 hash
- before/after state digest

4. 단위 타입
────────────────────────────────────────

필수 기본 단위:

- DistanceM
- AreaM2
- VolumeM3
- MassKg
- TimeSeconds
- DurationTicks

- EnergyJ
- PowerW
- TemperatureK
- PressurePa

- MoistureRatio

- HealthRatio01

규칙:

- Probability01과 Confidence01을 같은 타입으로 혼용하지 않음
- 섭씨는 입력·표시용이며 내부 열역학은 Kelvin 권장
- 각 단위 타입은 NaN·Infinity·유효 범위를 검증
