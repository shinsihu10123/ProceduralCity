38. 참조 무결성
────────────────────────────────────────

38.1 참조 종류

Strong Reference
- 대상이 반드시 존재해야 함
- 없으면 불변 조건 위반

Weak Historical Reference
- 대상이 파괴되어도 Tombstone으로 유지

Optional Reference
- 없음이 정상 상태

External Reference
- Asset, file, external database
- adapter를 통해 검증

38.2 삭제 정책

즉시 물리 삭제하지 않고 다음 순서를 권장한다.

active
→ pending_destruction
→ destroyed
→ tombstone
→ archived

38.3 순환 참조

메모리·관계·인과 그래프에서 순환은 의미상 가능하다.
직렬화는 ID 기반으로 수행해 객체 포인터 순환을 피한다.

40. Null과 Optional 규칙
────────────────────────────────────────

- 의미 있는 부재는 Optional로 표현
- 0, 빈 문자열, 음수를 부재 표현으로 사용하지 않음
- 필수 필드는 null 금지
- 알 수 없음과 존재하지 않음을 구분

예:
unknown temperature
≠ no temperature field
≠ zero temperature

Epistemic 값은 다음을 구분한다.
- unknown
- uncertain
- contradictory
- not_applicable
- known

43. 스키마 호환성
────────────────────────────────────────

변경 종류:

Compatible Additive
- optional 필드 추가
- 새 Event 타입 추가
- 새 enum 안정값 추가

Migration Required
- 필드 의미 변경
- 단위 변경
- 타입 변경
- 상태 소유권 변경
- 필수 필드 추가

Breaking
- ID 의미 변경
- 과거 Event 해석 불가
- 인과 링크 제거
- 저장 복원 불가

규칙:
- 모든 스키마 변경은 변경 종류 표시
- Migration Required 이상은 마이그레이션 제공
- 원본 저장 보존
- 변환 후 digest·불변 조건 검사
- 마이그레이션도 버전과 로그 기록

44. 데이터 보존과 압축

44.1 Event

- 압축 가능

- 장기 보존

- 영구 또는 매우 장기 보존

- 중요도 낮은 개별 기억은 요약 가능
- 절차 기억과 트라우마는 별도 정책
- 사건 링크가 있는 중요 기억은 보존

44.3 Relationship

- 세부 Interaction은 압축 가능
- 현재 신뢰·의무·원한과 주요 원인 사건 보존

44.4 Knowledge

- 전승 계보의 중요 분기 보존
- 동일 내용 중복은 내부 dedup 가능
- 소유자별 신뢰도는 별도 유지

44.5 Snapshot

- 체크포인트 간격 설정
- 오래된 세부 Snapshot은 삭제 가능
- 해당 시점 Event와 장기 Snapshot 정책 조합
