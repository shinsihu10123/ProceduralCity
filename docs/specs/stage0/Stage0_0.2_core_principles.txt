문서 버전: 0.2.0
상태: 기준안 확정
적용 범위: 프로젝트 전체

목적: 프로젝트 철학을 실제 설계·코드·데이터·테스트에서 위반하지 않도록 강제 규칙으로 변환한다.

⸻

1. 규칙 등급

본 문서에서는 다음 세 등급을 사용한다.

MUST

반드시 지켜야 하는 규칙이다.

위반 시 해당 기능이나 설계는 승인하지 않는다.

SHOULD

특별한 기술적 사유가 없다면 지켜야 하는 규칙이다.

위반할 경우 변경 기록에 다음을 남겨야 한다.

* 위반 이유
* 대안 검토 결과
* 예상되는 부작용
* 향후 수정 계획

MUST NOT

절대 허용하지 않는 규칙이다.

위반이 발견되면 기능을 제거하거나 재설계한다.

⸻

2. 원칙 P-01: 결과 비고정성

정의

시뮬레이션은 도시, 국가, 기술, 경제 체제, 정치 체제, 문화와 같은 고차원 결과를 미리 결정해서는 안 된다.

강제 규칙

P-01-01

시스템은 특정 수치 임계값만으로 고차원 사회 구조를 생성해서는 안 된다.

MUST NOT

금지 예시:

인구가 1,000명을 넘으면 도시 생성
교환 횟수가 100회를 넘으면 시장 생성
집단 인원이 300명을 넘으면 국가 생성

P-01-02

고차원 구조는 하위 상태와 상호작용의 누적으로 나타나야 한다.

MUST

도시와 유사한 상태는 다음과 같은 복수 요소의 결합으로 발생해야 한다.

* 인구 밀도
* 장기 거주
* 이동망
* 생산 시설
* 저장 시설
* 교환 빈도
* 노동 분화
* 공공 자원
* 행정 활동
* 기능적 공간 분화

P-01-03

관찰 시스템은 발생한 구조를 사후적으로 분류할 수 있다.

MAY

예를 들어 분석 계층이 특정 지역을 “고밀도 정착지” 또는 “시장 활동 지역”이라고 표시하는 것은 허용한다.

단, 이 분류가 시뮬레이션 상태를 자동으로 변경해서는 안 된다.

P-01-04

시뮬레이션에는 문명의 필수 최종 상태를 두어서는 안 된다.

MUST NOT

다음은 유효한 결과다.

* 장기간 정체
* 유목 생활 유지
* 반복적 붕괴
* 국가 미형성
* 기술 퇴행
* 전체 개체 멸종

⸻

3. 원칙 P-02: 인과성

정의

모든 중요한 상태 변화는 세계 내부의 원인으로부터 발생해야 한다.

강제 규칙

P-02-01

모든 상태 변경은 원인 주체 또는 원인 사건을 가져야 한다.

MUST

상태 변경 기록에는 최소한 다음이 포함되어야 한다.

* 변경 대상
* 변경 이전 상태
* 변경 이후 상태
* 직접 원인
* 발생 시간
* 발생 위치
* 관련 행위자
* 사용된 자원 또는 에너지
* 난수 사용 여부

P-02-02

원인 없는 자원 생성과 소멸은 금지한다.

MUST NOT

예외는 다음과 같다.

* 명시적으로 정의된 자연 생성
* 생태·지질·기후 과정에 의한 생성
* 시스템 초기화
* 기록된 실험자 개입
* 수치 오차 보정

P-02-03

복합 사건은 원인 사슬로 추적할 수 있어야 한다.

MUST

예:

강수량 감소
→ 토양 수분 감소
→ 식물 성장률 저하
→ 식량 공급 감소
→ 영양 부족
→ 이동 증가

P-02-04

확률적 사건도 조건과 확률 근거를 가져야 한다.

MUST

확률은 원인을 대체하지 않는다.

잘못된 예:

매일 1% 확률로 기근 발생

허용 가능한 예:

식량 공급 부족, 저장 손실, 이동 단절,
질병 확산 조건을 바탕으로 기근 위험 계산

⸻

4. 원칙 P-03: 복수 해결 경로

정의

행위자와 집단이 직면한 문제에는 가능한 한 하나 이상의 해결 경로가 존재해야 한다.

강제 규칙

P-03-01

핵심 생존 문제를 단일 행동으로만 해결하도록 설계해서는 안 된다.

MUST NOT

예를 들어 체온 저하 문제의 유일한 해결책을 불 사용으로 고정해서는 안 된다.

가능한 해결 경로:

* 불
* 의복
* 구조물
* 이동
* 활동 시간 변경
* 집단 밀집
* 신체 적응

P-03-02

각 해결책은 서로 다른 비용과 위험을 가져야 한다.

MUST

비교 요소:

* 필요한 시간
* 에너지
* 자원
* 지식
* 실패 확률
* 부상 위험
* 장기 유지비
* 다른 행위자와의 관계 영향

P-03-03

행위자는 항상 최적해를 선택하지 않아도 된다.

MUST

선택은 다음의 영향을 받을 수 있다.

* 제한된 정보
* 경험
* 기억 오류
* 성격
* 가치관
* 공포
* 사회적 압력
* 시간 부족
* 인지 능력

P-03-04

개발자가 예상하지 못한 해결 방식도 물리적으로 가능하면 허용해야 한다.

SHOULD

⸻

5. 원칙 P-04: 실패 가능성

정의

모든 의미 있는 행동, 기술, 구조, 제도는 실패하거나 예상과 다른 결과를 낼 수 있어야 한다.

강제 규칙

P-04-01

성공이 자동 보장되는 복합 행동은 금지한다.

MUST NOT

예:

* 재료만 있으면 건축 자동 성공
* 씨앗을 심으면 농업 자동 성공
* 기술 지식을 알면 제작 자동 성공
* 명령을 내리면 구성원이 자동 복종

P-04-02

실패는 결과 상태에 실제 영향을 남겨야 한다.

MUST

실패 결과 예:

* 자원 손실
* 시간 손실
* 부상
* 신뢰 하락
* 구조 손상
* 지식 수정
* 행동 회피
* 새로운 실험 발생

P-04-03

실패 확률은 행위자의 능력과 환경 조건에 따라 달라져야 한다.

MUST

P-04-04

반복 실패가 학습이나 포기를 유발할 수 있어야 한다.

MUST

P-04-05

실패는 단순 무작위 처벌로 사용해서는 안 된다.

MUST NOT

⸻

6. 원칙 P-05: 제한된 정보

정의

행위자는 세계의 실제 상태 전체에 접근하지 않는다.

강제 규칙

P-05-01

행위자 AI는 전역 시뮬레이션 상태를 직접 조회해서는 안 된다.

MUST NOT

금지 예:

가장 가까운 식량 자원의 실제 좌표를 전역 검색
적대 집단의 정확한 병력 조회
아직 방문하지 않은 지역의 지형 정보 사용

P-05-02

행위자가 사용하는 정보는 출처를 가져야 한다.

MUST

정보 출처:

* 직접 관찰
* 기억
* 타인 전달
* 기록물
* 추론
* 소문
* 집단 지식

P-05-03

인지된 정보와 실제 세계 상태를 분리해야 한다.

MUST

예:

실제 상태: 강 건너 식량 존재
행위자 인식: 해당 지역은 위험하다고 믿음

P-05-04

정보에는 정확도, 신뢰도, 생성 시간, 출처를 저장해야 한다.

MUST

P-05-05

오해, 기만, 소문, 정보 지연이 가능해야 한다.

SHOULD

⸻

7. 원칙 P-06: 역사성과 경로 의존성

정의

과거의 사건과 결정은 이후 세계의 가능성과 행위에 지속적인 영향을 미쳐야 한다.

강제 규칙

P-06-01

세계의 중요한 상태는 매 틱마다 초기화하거나 현재 값만으로 다시 계산해서는 안 된다.

MUST NOT

P-06-02

다음 요소는 역사 상태를 유지해야 한다.

MUST

* 개체 기억
* 관계 변화
* 신뢰와 원한
* 자원 이용 흔적
* 이동 경로
* 구조물 손상
* 토양 변화
* 기술 전승
* 집단 규칙
* 영토 점유
* 언어와 문화 변화

P-06-03

같은 현재 조건이라도 과거가 다르면 다른 선택과 결과가 나타날 수 있어야 한다.

MUST

P-06-04

역사 정보는 무제한으로 모두 보존하지 않아도 된다.

MAY

단, 요약·압축 과정에서 이후 행동에 영향을 주는 정보는 유지해야 한다.

P-06-05

역사 압축은 원인 추적 기능을 파괴해서는 안 된다.

MUST NOT

⸻

8. 원칙 P-07: 실제 기능을 가진 지식과 기술

정의

기술은 단순한 이름이나 해금 상태가 아니라, 세계에서 실제 작동하는 지식과 행동의 조합이어야 한다.

강제 규칙

P-07-01

기술 트리 기반 자동 해금은 금지한다.

MUST NOT

P-07-02

기술은 다음 요소로 표현해야 한다.

MUST

* 대상 물질 또는 현상
* 필요한 조건
* 수행 행동
* 예상 결과
* 성공 경험
* 실패 경험
* 신뢰도
* 전파 경로
* 재현 가능성

P-07-03

기술 이름을 몰라도 기능을 사용할 수 있어야 한다.

MUST

행위자는 “연소”라는 개념명이 없어도 마른 물질과 열의 관계를 경험적으로 이용할 수 있다.

P-07-04

기술은 부분적으로 학습될 수 있어야 한다.

MUST

예:

* 불을 유지하는 법은 알지만 점화법은 모름
* 금속을 가열할 수 있지만 합금 원리는 모름
* 씨앗을 심지만 계절 조건을 모름

P-07-05

기술은 잊히거나 왜곡될 수 있어야 한다.

MUST

⸻

9. 원칙 P-08: 물리적·생물학적 제약

정의

행위자의 행동과 문명 발전은 세계의 실제 자원·에너지·시간·거리·신체 조건에 의해 제한되어야 한다.

강제 규칙

P-08-01

모든 행동은 시간을 소비해야 한다.

MUST

P-08-02

물리 행동은 에너지 또는 자원을 소비해야 한다.

MUST

P-08-03

물체는 즉시 이동하거나 순간적으로 제작되어서는 안 된다.

MUST NOT

P-08-04

건축과 제작은 실제 재료 공급과 운반 과정에 의존해야 한다.

MUST

P-08-05

거리와 지형은 이동 비용에 영향을 주어야 한다.

MUST

P-08-06

행위자의 신체 능력은 행동 가능 범위를 제한해야 한다.

MUST

제약 예:

* 운반 가능 질량
* 이동 속도
* 피로
* 체온
* 부상
* 감각 범위

⸻

10. 원칙 P-09: 미시 상태와 거시 상태의 분리

정의

도시·국가·경제 등 거시 구조는 미시 상호작용에서 발생하지만, 성능상 거시 모델로 축약할 수 있다.

강제 규칙

P-09-01

미시 상태와 거시 상태 사이의 변환 규칙을 명시해야 한다.

MUST

P-09-02

거시 모델은 미시 상태에서 불가능한 결과를 만들어서는 안 된다.

MUST NOT

P-09-03

축약 지역에서도 자원·인구·에너지·지식의 보존 관계를 유지해야 한다.

MUST

P-09-04

해상도 전환은 숨은 보너스나 패널티를 생성해서는 안 된다.

MUST NOT

P-09-05

사용자가 지역을 확대했을 때 축약 상태를 세부 상태로 복원할 수 있어야 한다.

MUST

P-09-06

복원된 개체와 물체는 축약 기간의 통계와 모순되지 않아야 한다.

MUST

⸻

11. 원칙 P-10: 시뮬레이션과 렌더링 분리

정의

시뮬레이션 세계는 화면에 표시되지 않아도 독립적으로 작동해야 한다.

강제 규칙

P-10-01

렌더링 프레임 속도가 시뮬레이션 결과를 변경해서는 안 된다.

MUST NOT

P-10-02

화면 밖의 세계도 정의된 해상도에 따라 계속 진행되어야 한다.

MUST

P-10-03

시각 효과가 실제 세계 상태를 생성해서는 안 된다.

MUST NOT

예:

* 화면상 불꽃만 존재하고 열이나 연소 상태가 없음
* 차량 애니메이션은 움직이지만 실제 물류 이동은 없음
* 전투 연출은 있지만 개체 충돌과 피해 계산은 없음

P-10-04

모든 주요 시각 표현은 대응하는 시뮬레이션 상태를 가져야 한다.

MUST

P-10-05

헤드리스 실행을 지원하도록 설계해야 한다.

SHOULD

헤드리스 실행은 렌더링 없이 시뮬레이션만 구동하는 방식이다.

⸻

12. 원칙 P-11: 결정론과 확률

정의

시뮬레이션은 동일 조건 재현이 가능해야 하지만, 확률적 다양성도 허용한다.

강제 규칙

P-11-01

모든 난수 생성은 관리되는 난수 시스템을 사용해야 한다.

MUST

P-11-02

난수 시드를 저장해야 한다.

MUST

P-11-03

동일한 버전, 초기 상태, 설정, 시드에서는 가능한 한 동일한 결과를 재현해야 한다.

SHOULD

P-11-04

확률은 물리적·생물학적·인지적 불확실성을 표현하기 위해 사용한다.

MUST

P-11-05

23. 기능 설계 승인표

검토 항목	필수 답변
해결하려는 문제	이 기능이 어떤 세계 현상을 표현하는가
원시 입력	어떤 하위 상태를 사용하는가
출력 상태	무엇이 변경되는가
비용	시간·에너지·자원 비용은 무엇인가
실패	어떻게 실패할 수 있는가
대안	다른 해결 방식이 존재하는가
정보	행위자는 어떤 정보로 판단하는가
역사	과거 경험이 어떻게 반영되는가

테스트	어떤 불변 조건을 검증하는가

한 항목이라도 답할 수 없으면 설계 미완성으로 처리한다.

24. 예외 승인 절차

핵심 원칙을 예외적으로 완화해야 하는 경우 다음 절차를 따른다.

1. 위반되는 원칙 번호를 명시한다.
2. 기술적으로 원칙을 준수할 수 없는 이유를 기록한다.
3. 가능한 대안을 최소 두 개 검토한다.
4. 결과 왜곡 범위를 분석한다.
5. 임시 조치인지 영구 조치인지 구분한다.
6. 제거 또는 개선 조건을 정한다.
7. 변경 기록에 남긴다.

다음 원칙은 예외 승인 대상이 아니다.

* 숨은 개입 금지
* 전역 정보 AI 금지
* 원인 없는 상태 변경 금지
* 렌더링이 시뮬레이션 상태를 대신하는 행위 금지
* 고정된 문명 발전 경로 강제 금지

25. Stage 0.2 검증 시나리오

시나리오 A: 도시 발생

잘못된 구현:

인구가 1,000명을 초과하면 도시 객체 생성

올바른 구현:

* 일정 지역에 인구와 생산 활동이 집중된다.
* 저장·교환·이동·전문 행동이 반복된다.
* 구조물과 이동로가 누적된다.
* 분석 계층이 이를 고밀도 복합 정착지로 분류한다.

시나리오 B: 불 발견

잘못된 구현:

행위자가 나무를 10회 채집하면 불 기술 해금

올바른 구현:

* 열원과 가연물의 상호작용이 발생한다.
* 행위자가 열과 연소를 관찰한다.
* 경험을 기억한다.
* 유사한 조건을 재현한다.
* 성공률이 높아지며 지식이 전파된다.

시나리오 C: 국가 형성

잘못된 구현:

정착지 세 개가 존재하면 국가 생성

올바른 구현:

* 집단 간 반복적 협력과 갈등이 발생한다.
* 자원·방어·규칙 집행을 담당하는 조직이 형성된다.
* 구성원이 권한을 인정하거나 강제로 복종한다.
* 장기간 여러 정착지에 통제력이 유지된다.
* 분석 계층이 국가에 가까운 정치 조직으로 분류한다.

시나리오 D: 원거리 지역 축약

잘못된 구현:

화면 밖 지역은 정지

또는

무작위로 인구와 자원을 변경

올바른 구현:

* 집단 단위 생산·소비·출생·사망·이동을 계산한다.
* 자원과 인구 보존 관계를 유지한다.
* 확대 시 집단 통계에 맞는 개체 상태를 복원한다.

1. 결과가 아니라 결과가 발생할 수 있는 조건을 만든다.
2. 문명 발전 순서를 강제하지 않는다.
3. 모든 중요한 변화는 세계 내부 원인을 가진다.
4. 행위자는 제한된 정보만 사용한다.
5. 동일한 문제에는 복수 해결 경로가 존재할 수 있어야 한다.
6. 모든 복합 행동과 제도는 실패할 수 있다.
7. 시간·거리·에너지·자원·신체 조건을 무시하지 않는다.
8. 과거 사건은 미래 가능성을 변경한다.
9. 기술은 실제 기능과 전승 가능한 지식으로 존재한다.
10. 집단·도시·국가는 하위 상호작용에서 발생한다.
11. 시뮬레이션과 렌더링을 분리한다.
12. 근사 모델은 인과관계를 유지해야 한다.
13. 숨은 보정과 비공개 개입을 금지한다.
14. 주요 결과의 원인과 결과를 추적할 수 있어야 한다.
15. 저장된 세계는 중단 전 상태에서 논리적으로 계속되어야 한다.
16. 예상하지 못한 결과도 물리적·인과적으로 유효하면 허용한다.
