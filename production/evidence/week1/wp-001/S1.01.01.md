## Implemented boundary

The code makes `S1.01.01` an executable validation contract. It does **not** yet implement later registry, transaction, scheduler, persistence format, or commit authority work.

Implemented checks:

1. Required `fact_key`, `version`, `owner`, `writer`, `state_class`, `transition`, `causal_parent`, and `origin` are present and non-empty where applicable.
2. Contract version is explicit and stale/unsupported versions are rejected.
3. Only canonical semantic planes are accepted.
4. Derived/Observer/Renderer/Analytics state cannot be registered as canonical.
5. Only the owning resolver path can submit a canonical candidate; UI/AI/Observer/Renderer/Analytics and unmediated cross-domain writes are rejected.
6. Writer must match the declared semantic owner.
7. Successful validation produces a versioned receipt that retains `Canonical`, `Authority`, `Registry`, and the causal parent reference.
8. Validation is side-effect free: failed speculative candidates cannot mutate canonical state.
