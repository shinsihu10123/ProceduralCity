## Frozen acceptance basis

S1.02.03 processes the frozen feature keys `Persistent`, `Lifecycle`, `Machine`, `Stable`, and `Entity`, together with creation/active/inactive/termination state, an explicit allowed-transition set, the current target state, and the confirmed predecessor cause event. It must compare the current state and cause against the supplied allowed transition and produce a versioned lifecycle candidate/outcome with causal evidence.

The L3 must not turn a title word, score, camera value, Observer/Renderer/Analytics output, out-of-scope state, missing cause, wrong owner, stale version, unsupported transition, or incomplete operation into Canonical Reality. Actual mutation remains downstream behind Objective Resolution and the designated PA-003 canonical owner commit path. Candidate remains distinct from Reality.

The source states that allowed transitions are read state but does not enumerate a fixed global transition graph here. Therefore this implementation validates an explicit caller-supplied allowed-transition set rather than inventing additional transition semantics in S1.02.03.

## Implementation

Implemented `PersistentLifecycleProcessor` with:

- explicit `Created`, `Active`, `Inactive`, and `Terminated` source states corresponding to the Frozen creation/active/inactive/termination state vocabulary;
- explicit `LifecycleTransition { from, to }` candidate transition identity;
- direct S1.02.02 predecessor validation for work identity, schema, owner, completion phase, CandidateOnly disposition and Frozen root continuity;
- Stable ID, namespace, namespace schema/version and lifecycle-lineage continuity;
- required confirmed cause event and explicit allowed-transition membership check;
- PA-003 owner/writer checks and OwningResolver-only write-origin boundary;
- Requested / InProgress / Partial / Complete / Failed distinction, with only Complete eligible for a successful candidate outcome;
- non-authoritative display/projection/unrelated-state hints excluded from lifecycle outcome authority;
- deterministic evidence digest plus snapshot/restore for persistence and replay;
- `pending_transition`, previous state, candidate state, machine step, operands and predecessor causal evidence in output;
- successful output remains `CandidateOnly`; no Canonical Commit is performed.

This L3 does not pre-implement S1.02.04 Committed Entity Creation Boundary, S1.02.05 Deactivation / Death / Retirement State, tombstone retention, cross-reference integrity, reuse audit, or later canonical transaction/commit work.

## Test mapping

- BEHAVIOR_NORMAL: valid state + confirmed cause + supplied allowed transition produces the direct CandidateOnly lifecycle result.
- BEHAVIOR_FAILURE: missing cause, stale S1.02.02 schema reference, and a transition absent from the allowed set are rejected without a successful result.
- BOUNDARY: Requested/InProgress/Partial/Failed do not count as Complete; unrelated projection/display state does not change the lifecycle outcome.
- AUTHORITY: wrong owner/writer and Derived/Observer/Renderer/Analytics origins are rejected.
- CONTRACT: Frozen root ID/version/owner/causal parent and the exact S1.02.02 evidence digest are preserved.
- INTEGRATION: Frozen root → S1.02.01 → S1.02.02 → S1.02.03 succeeds without shortcut; root mismatch or incomplete predecessor propagates failure.
- PERSISTENCE: snapshot/restore preserves Stable ID, namespace version, pending transition, causal reference and evidence digest.
- REPLAY: identical snapshot/event/outcome/schema/predecessor produces identical result, operand order, pending transition and digest.
