## Frozen acceptance basis

S1.02.05 is the versioned state-representation boundary for `Deactivation`, `Death`, `Retirement`, `Stable`, and `Entity`. It reads the Frozen WHAT/HOW root contract, current deactivation/death/retirement state/event/reference data, the PA-003 owner contract, Stable ID, version, WorldTime and causal parent. The source-defined owner alone may create, update or end the record, and similar-named out-of-scope or observational values cannot replace it.

A valid operation must distinguish changed fields from preserved fields, retain the Stable ID, lineage and predecessor causal reference, require the state field/unit/frame/version and a cause event, and validate that the requested lifecycle transition belongs to the supplied source-defined transition set. Duplicate state-record ID, dangling reference, stale update/version, wrong owner/writer, incomplete operation, out-of-scope subject or reverse-write origin must not yield a successful result or a Canonical partial result.

The Frozen invariant remains unchanged: PA-003 keeps canonical ownership; Candidate != Reality; only the designated owner after Objective Resolution may Canonical Commit; read-only Observer/Renderer/Analytics/Derived paths cannot write backward into Canonical Reality.

## Implementation

Implemented `TerminalStateProcessor` with:

- explicit `TerminalStateKind::{Deactivation, Death, Retirement}` rather than inferring terminal meaning from names or thresholds;
- explicit record operations `Create`, `Revise`, and `CloseRecord`;
- unique state-record ID validation on create;
- revision/closure continuity requiring the same state-record ID, Stable ID and lineage plus exact prior-version increment;
- closed-record revision rejection;
- direct S1.02.04 predecessor validation for work identity, schema, owner, completion, CandidateOnly disposition, reference integrity and Frozen root continuity;
- exact predecessor evidence-digest continuity;
- Stable ID, entity-kind and creation-provenance preservation;
- explicit current/target lifecycle states and a caller-supplied allowed-transition set, with no invented global transition graph;
- explicit source-defined cause event;
- opaque WorldTime instant/unit/frame/version validation;
- explicit lineage reference and verified reference-integrity requirement;
- PA-003 owner/writer checks and OwningResolver-only write-origin boundary;
- `EntityLifecycleState` versus `ProjectionOnly` / `SimilarNamedOutOfScopeState` separation;
- Requested/InProgress/Partial/Failed distinction inherited through the shared operation phase, with only Complete eligible for success;
- output metadata that distinguishes changed fields (`lifecycle_state`, `terminal_state_kind`, `world_time_reference`, `cause_event`) from preserved fields (`stable_id`, `lineage_reference`, `entity_kind`, `creation_provenance`);
- deterministic evidence digest and snapshot/restore for persistence/replay;
- successful output remains `CandidateOnly`; no Canonical Commit is performed.

This L3 does not pre-implement S1.02.06 tombstone retention, S1.02.07 cross-reference integrity contract, S1.02.08 snapshot/reload continuity, S1.02.09 reuse prohibition audit, or later canonical transaction/commit semantics.
