## Exact pipeline finding

Canonical order is:

`supply.beginMonth()`
→ firm decision
→ `banking.originateCredit()`
→ labor
→ `supply.planProduction()`
→ `supply.procureInputs()`
→ production.

`supply.beginMonth()` explicitly resets `f.supplyShortage = 0`. The bank's firm application then computes:

`inputNeed = supplyShortage × price`

before current-month planning/procurement has occurred.

P75 observes the resulting state directly: every first-cycle downstream entrant credit observation has `inputNeedObservedAtCredit = 0`, while every corresponding first-cycle downstream lifecycle row later shows positive supply shortage and zero input spend.

The working-capital target at first credit cycle is therefore driven by payroll/safe-cash terms but is blind to the downstream entrant's current-month intermediate-input requirement.

## Interpretation

P48 showed that replacement entrants are born with zero cash and downstream zero input inventory. P52 showed that supplying physical input makes downstream entrants capable of producing. P75 now closes the financing path around those findings.

The failure is **not** that entrants fail to ask for credit, and it is **not** that the application queue crowds them out:

- mechanical application eligibility = 100% for observed credit cycles;
- actual queue inclusion = 100%;
- actual credit origination = 0%.

Therefore a rejection/capital constraint occurs after queue admission. At the same time, the application amount is structurally understated with respect to downstream inputs because the model's only input-need signal has been reset to zero before credit is evaluated.

RESOURCE entrants can sometimes hire and produce without intermediate inputs, but most do not earn revenue and re-exit remains high. Downstream entrants cannot cross the input barrier at all in the observed bounded paths.
